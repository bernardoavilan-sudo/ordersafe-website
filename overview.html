Technical Overview

For CTOs, Risk Engineers, and Security Auditors: This page details the internal mechanics of the OrderSafe Offensive Engine.

The Problem with Legacy Systems

Traditional fraud engines (like Stripe Radar or basic Sift implementations) rely heavily on AVS (Address Verification System) and CVV checks. Professional cybercriminals bypass these using Non-VBV BINs (cards with no 3D Secure) and Anti-Detect Browsers (like AdsPower or Dolphin Anty) paired with residential proxies.

Our Detection Methodology

OrderSafe ingests transaction metadata via our REST API. Instead of just checking the card, we correlate the transaction context:

  • Environment Analysis: We detect VM fingerprints and headless browsers (Rules R12, R92, R93).
  • Behavioral Patterns: We analyze checkout speed and mouse movements (Rule R97, R60).
  • Network Reputation: We flag datacenter IPs and known proxy ranges (R42, R96).
  • Identity Convergence: We compare the shipping country, billing country, and IP geolocation (R36, R46).

The Scoring Algorithm

The system assigns weights to triggered rules. If critical rules are activated (e.g., a Non-VBV attack paired with a datacenter IP), our Absolute Override system forces the score to 10.0 and the action to BLOCK, preventing the payment from being captured.
